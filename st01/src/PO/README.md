# PO — OMS 코어 공유 부문 (시장 무관 크로스커팅)

시장 재편 A안(설계 §5-3, §8-2 운영자 확정): letter=시장이되, **시장에 종속되지 않는
크로스커팅 기능은 PO 한 곳**으로 모은다.

## 담는 기능 (현 PA에서 분리해 이관)
- 자동전략 (5xxx)
- 한도/리스크 관리 (9xxx)
- 접속서버/클라이언트 통신 (8xxx)
- 응답분배 (1200계 분배 로직)
- 미니원장

> 현 PA에서 시장별 주문/체결(1xxx·2xxx)을 시장 모듈(pa_/pb_/pc_)로 빼내면
> 남는 잔여분이 정확히 PO다. libfepP.a(시장 무관 코어)는 이미 분리돼 있으므로,
> PO는 "라이브러리로 내리기엔 업무성이 있는 공유 프로세스"들의 집.

## 위치
- 소스 `st01/src/PO/po_*.c`, 오브젝트 `st01/obj/PO/`
- 빌드 `mk.sh po` (소스 0개면 no-op). `_FEP_SUBDIR`에 `O` 포함 → `all`/`src`에도 편입.
- 런타임 FIFO `st02/FIFO/PO`, DAT `st02/DAT/PO`, LOG `st03/LOG/PO`

## 빌드모델
PC와 동일(설계 §6): 1 소스 = 1 바이너리, 인스턴스는 proc.ini + `exec -a` argv[0]로 구분.

## SHM
전략(`STRRG_SHM_KEY`)·미체결(`MK_PM_SHM_KEY`)·한도(`RISK_SHM_KEY`)는 이미
**전 시장 공유 세그먼트**(shm_memory.h, base 0x41000000). PO가 이들의 1차 소유/관리자가 된다.
letter별 신규 SHM 키는 불필요(의미별 세그먼트 유지).

## 마이그레이션 순서 (설계 §7)
2단계(PO 추출)는 3단계(pc_ 파일럿)와 병행 가능. pc_ 프로토콜 대면부(주문송신/응답체결수신/시세) 완료 후 PO 추출 착수(응답분배부터).
