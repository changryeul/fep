## 1. 결함 목록

### 결함 A — `if (item_su_michecnt = 0)` 대입 오타 (심각)

`pa_1490_mp.c:523`(근월물 매수), `:587`(원월물 매수/스프레드): `==`가 아닌 `=`.
- 조건이 항상 거짓 → 미체결 금액(`item_su_miche_gum`) 0 리셋이 절대 실행되지 않음
- **부작용: 매수 체결마다 `item_su_michecnt`가 무조건 0으로 덮어써짐** → 매수 미체결 수량 기반 한도 계산이 지속적으로 오염
- 매도 분기(:534, :595)는 `<= 0`으로 정상이나, `else if (< 0)` 음수 경고가 도달 불가(<=0에 흡수) — 4분기 모두 음수 이상 감지가 작동하지 않음

**수정**: 4분기 모두 아래 구조로 통일 (매도 분기의 기존 동작 `<=0 → gum=0` 보존 + 음수 경고 복원):

```c
if (cnt <= 0) {
    if (cnt < 0)
        Log(USR_ERROR, "한도계산 이상함, ...");
    gum = 0;
}
```

### 결함 B — 루프 내부의 `i >= MAX_MICHE` 데드코드 7곳

`for (i = 0; i < MAX_MICHE; i++)` 본문 안의 `if (i >= MAX_MICHE)`는 루프 조건상 도달 불가. 주석과 로그 문구가 명확히 의도를 보여주는 미작동 로직:

| # | 위치 | 의도된 동작 (현재: 조용히 통과) | 수정 |
|---|------|------|------|
| B-1 | `pa_1490_mp.c:301` | 체결 도치: 3초(1번째)/60초(2번째) sleep × 3회 재검색, 초과 시 재처리 FIFO Write 후 skip. **현재는 못 찾은 체결이 od_price=0으로 한도 계산에 유입** | 검색부(F6 캐시+폴백)를 `while(1)` 래핑, 못찾음 시 retry 블록 실행 |
| B-2/B-3 | `pa_1290_mp.c:405`, `:786` | 미체결 만석 시 10초 대기 후 재검색. 현재는 등록 소실 | 삽입 for를 `while(1)` 래핑 |
| B-4/B-5 | `pa_1290_mp.c:468`, `:856` | 원주문 못찾음: 오류 로그 + NOTOK. 현재는 조용히 통과 후 낡은 org_gum/org_cnt로 한도 로직 진행 | 블록을 루프 종료 후로 이동 |
| B-6/B-7 | `pa_1290_mp.c:669`, `:948` | 자동취소 주문번호 못찾음: 오류 로그 + NOTOK | 블록을 루프 종료 후로 이동 |

**파급 검토**: `Make_MiChe` 리턴값(`rt`)은 호출부(Analyze_Data)에서 미사용 — NOTOK 복원은 로그 기록 외 흐름 변화 없음. B-1의 sleep 재시도는 단일 스레드 이벤트 루프를 최대 9초(1번째)/180초(2번째) 블로킹 — **원래 설계된 동작**이며 도치는 희귀 이벤트. B-2/3의 만석 대기는 10,000건 만석이라는 비정상 상태의 배압(back-pressure)으로 원설계 의도.

## 2. 검증

- 단위 테스트 불가(전 지점이 SHM 전역 결합) — 프로젝트 선례(§3.x 보안 수정들)에 따라 컴파일 전 변형(A1291/A2291/A1491/A1492/A2491/A2492) 검사 + 코드 리뷰 + 서버 전체 빌드로 검증. 도치/만석 시나리오는 integ 환경 구축(F5 하니스) 후 재현 테스트 추가 예정.
- `-Wparentheses` 경고 0 확인 (결함 A 수정 후).
