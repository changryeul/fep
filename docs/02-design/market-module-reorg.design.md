## 1. 배경 · 목적

증권사 시장 구조에 맞춰 **시장별로 소스를 소유·개발**하려는 것이 원래 부문 letter(`pa_`,`pb_`,…) 도입 취지다. 그러나 현재는 letter가 시장이 아닌 **계층(tier)** 으로 쓰이고 있어 목적과 어긋난다. 본 설계는 letter를 시장 축으로 정렬(A안)하고, 이를 가로막는 두 가지 얽힘(계층·크로스커팅)과 빌드 모델을 함께 정리한다.

## 2. 현행 구조 정밀 진단 (매뉴얼 + 코드 확인)

### 2.1 부문코드(letter) — 공식 규약상 `b~v`는 예비
매뉴얼 2.2.3: (1)시스템구분 `P` + (2)업무구분 `a`=시스템트레이딩, **`b~v`=예비**, `x`=utility, `z`=관리. SHM 키가 letter로 분리(`0x2101` a, `0x2102` b, `0x2103` c …) → **letter마다 독립 SHM 세그먼트**.

### 2.2 "시장"은 letter가 아니라 함수코드 앞자리에 있음
- 업무구분코드 대분류(=상품구분): 실사용 **1=채권, 2=파생** 주문/체결. (+5=전략, 6=조회, 7=시세, 8=접속서버, 9=초기화)
- 운영시간표 증거: **PA(OMS)** 가 채권(1xxx)+파생(2xxx)+전략(5xxx)+한도(9xxx)+접속(8xxx)을 모두, **PB(FEP)** 도 `pb_1101`(채권주문)·`pb_2101`(파생주문)·`pb_1201/2201`(채권/파생 체결)을 모두 처리.
- ⇒ **현 letter = 계층**(a=OMS 응용, b=KRX 대면 FEP), **시장 = 함수코드 앞자리**.

### 2.3 빌드: 한 소스 → `-D`로 다중 바이너리
- `pb_7100_ts.c` → `-DB1401/1402/1403/1411`로 **4개 바이너리**(포워더 인스턴스 차이뿐)
- `pb_1200_tr.c` → `-DB1201`(채권체결)·`-DB1211`(DR카피)로 2개 + `#if defined(B1201)||defined(B1211)` 로 `DATA_SIZE`/동작 분기
- 즉 **(a) 시장/역할 차이와 (b) 프로세스 인스턴스 차이**가 모두 컴파일타임 `-D` + 소스 내 `#ifdef`로 뒤섞임. 가독성 저하, 변경 시 상호 간섭, 시장 로직이 전처리 분기에 매몰.

## 3. 목표 아키텍처 (A안) — 3원칙

1. **letter = 시장** (거래소 대면 주문·체결·시세만). **전 시장 KRX-direct 형태로 통일**(2026-08-06 확정): 파생의 IMECO(별도 기관 경유)는 폐기하고 거래소 직접 접속 형태로 감 → 현물/채권/파생이 같은 KRX 게이트웨이 메시지 계열. 따라서 분리 근거는 "프로토콜"이 아니라 **업무/상품/운영 오너십 + SHM 격리**.
   | letter | 시장 | 포함(상품유형) | SHM 키 |
   |--------|------|---------------|--------|
   | `pa_` | 현물(주식) | 유가증권(KOSPI)·코스닥·ELW·**ETF·ETN** | 0x2101 |
   | `pb_` | 채권 | KTS 국채전문·일반채권·RP | 0x2102 |
   | `pc_` | 파생 | 지수·주식·상품·통화·국채 선물옵션 (**KRX-direct**, IMECO 아님) | 0x2103 |
   | `pd_` | 예비 | 해외/글로벌·장외 등 | 0x2104 |
   | `po_` | OMS 코어(공유) | 전략·한도·접속서버·분배·미니원장 | (letter 위치) |
   | `px_/pz_` | 유틸/관리 | 현행 유지 | — |

   ETF/ETN/ELW는 **별도 letter가 아니라 현물(`pa_`) 내 상품유형**(타사 Meritz 사례 확인 §10).
2. **계층(OMS 응용 vs KRX FEP) = 배포 토폴로지** (letter 아님). 한 시장 모듈이 config/기동인자로 OMS측·FEP측 역할을 분담. (선례: 매뉴얼이 PB를 `PB/시세`·`PB/주문` 두 배포로 운영)
3. **크로스커팅 = 공유** (자동전략 5xxx·접속서버 8xxx·한도 9xxx·응답분배/미니원장). 시장을 가로지르므로 한 시장 letter에 두지 않음. → 아래 §5.

## 4. 함수코드 규약 (시장에서 해방 → 기능 통일)

letter가 시장을 담으므로, 함수코드 앞자리는 **순수 기능**으로 통일한다. `pa_1101_ts`·`pb_1101_ts`·`pc_1101_ts`가 각 시장의 "주문송신"으로 동일하게 읽힌다.

| 대역 | 의미 | 소속 |
|------|------|------|
| 1xxx | 주문송신/응답/체결/미체결 | 시장별 (pa/pb/pc) |
| 6xxx | 조회/배치 | 시장별 |
| 7xxx | 시세 수신/분배 | 시장별 |
| 8xxx | 접속서버(클라이언트) 송수신 | **공유** |
| 5xxx | 자동전략 | **공유** |
| 9xxx | 한도/리스크·메모리초기화 | **공유** |

중분류(2번째)는 매뉴얼 유지: 1=주문, 2=주문확인, 4=체결. 업무처리코드(mp/ts/tr/dd/…)도 유지.

## 5. 공유 / 시장 분리선

세 계층으로 나눈다:

1. **libfepP.a (시장 무관 코어)** — 이벤트 루프, TCP/UDP, SHM, 설정로더, 로그, 시퀀스, fd캐시, 미체결 인덱스. **이미 존재**하며 PA/PB 중복제거(`fep_common.c`/`FmtPtr`) 패턴이 검증됨. 신규 작업 아님, 계속 활용.
2. **시장 모듈 pa/pb/pc (얇게)** — 각 시장의 {전문 구조체 + 시장 업무규칙(호가유형·틱·거래시간·한도규칙)}. **전 시장 KRX-direct 통일**로 공용 KRX 코덱을 libfepP.a에서 공유(IMECO 별도 코덱 없음). 시장 모듈은 struct/업무규칙만 차별화 → 매우 얇아짐.
3. **OMS 코어 공유 부문 (신규 or 재명명)** — 자동전략·한도·접속서버·응답분배·미니원장. **현 PA에서 시장별 주문/체결(1xxx·2xxx)을 빼내면 남는 잔여분이 정확히 이것**. letter는 운영자 결정(§8-2): 신규 공유 letter(예: `po_` OMS-core) vs `pz_`(관리) 인접 배치.

### 5.1 부문 간 SEAM — SHM 키 조사 결과 (2026-08-06 확정)
po_(OMS코어)와 pc_/pb_(시장)가 나뉘면 부문 간 데이터 전달(seam)이 필요. 실측·코드 조사 결과:

- **파일큐·DSHM 큐는 부문별 키** — DSHM 세그먼트 키 = `BASE_SHM_KEY + (p_cnt+1)<<16 + segment` 로 **처리 부문(p_cnt)에 종속**(pz_memory_conf.c:1006-1013; PB=0x42020000, PO=0x42150000 확인). 파일큐 카운터(w_cnt/r_cnt)도 부문별 SHM(`Shm_Mem[D_K]`)에 상주. **∴ 생산자·소비자가 다른 부문이면 파일큐/DSHM 큐로 직접 연결 불가**(카운터 미동기, E2E로 확인).
- **의미별 세그먼트는 전역 공유** — 전략(`STRRG_SHM_KEY`)·미체결(`MK_PM_SHM_KEY`)·한도(`RISK_SHM_KEY`)·시세(`NOTE/FF`)는 **고정 전역 키(0x41000001~30, +test)** 로 `Sise_SHM`(shmsub.c)이 어느 부문에서든 같은 키로 attach → **본래 크로스부문 공유**. → **po_(미체결/한도/전략) 이관의 상태 공유는 문제 없음**(pc_/pb_/po_ 모두 같은 전역 세그먼트 attach).

**설계 결론 (seam 규칙)**:
1. **크로스커팅 STATE**(미체결·한도·전략·시세) → 기존 **전역 의미별 SHM** 그대로 사용. po_ 이관해도 attach 키 동일. ✅ 추가 작업 없음.
2. **부문 간 QUEUE 핸드오프**(예: pc_ KRX수신 → po_ 분배) → **운영자 결정: (c) STATE-driven (2026-08-06 확정)**.
   - pc_/pb_ 수신이 체결/응답을 **전역 SHM(미체결 MK_PM·체결·전략 STRRG 등 고정 전역키)에 직접 기록**, po_ 처리 프로세스가 그 전역 상태를 이벤트/폴링으로 소비. **부문 간 큐(파일/DSHM) 불필요**.
   - **근거·정합성**: 이 방식은 **이미 프로덕션에서 입증된 메커니즘** — 현 시스템이 미체결/한도/전략을 전역 고정키 SHM으로 전 부문 공유하는 것이 곧 STATE-driven. 따라서:
     - **po_ 미체결(pa_1290)·체결원장(pa_1490)·체결(pa_1400)·한도(pa_9001) 이관 = 프로세스만 po_로 옮기고 동일 전역 SHM(MK_PM/RISK) attach 유지** → **seam 자동 해결, 추가 배관 없음.**
     - **분배(po_1200_mp)의 전략 fan-out**(→per-전략 DSHM)은 **po_ 내부(전략 프로세스도 po_ co-locate)라 부문내 DSHM으로 유지** — 크로스부문 아님.
     - 남는 유일 항목: pc_/pb_ **수신이 전역 체결/응답 SHM에 기록하는 write 경로 신설**(현 파일큐 write → 전역SHM write로 교체). 미체결/체결 정합성 핵심이라 **replay/멱등 검증 하니스 선행 필수**(§7 주의).

#### 5.1.1 SEAM 스테이징 큐 구현 (2026-08-07 확정 — 전역 SHM 링버퍼)
운영자 결정: **전역 스테이징 SHM 큐**. po_ 미체결/체결 등록 로직을 **무변경 보전**하고, 수신→po_ 메시지 전달만 전역 고정키 링버퍼로 교체.
- **세그먼트**: `SEAM_Q_SHM_KEY = 0x41000015`(RISK 0x14~ITEM 0x30 사이 빈 키, +TEST 0x01000000). `inc/seam_queue.h` 정의, `sub/seam_queue.c` 구현(libfepP.a).
- **레이아웃**: `SEAM_SHM{ magic; SEAM_QUEUE q[NQUEUE] }`. 큐 2개 — `q[0]=응답`(회원처리호가), `q[1]=체결`. 각 큐 = `{ w_seq; r_seq[NREADER]; dropped[NREADER]; slot[SLOTS][RECSZ] }` 링버퍼. SLOTS=4096, RECSZ=400.
- **리더 인덱스(고정)**: 응답 큐 — `R_MICHE=0`(po_1290_mp 미체결), `R_DIST=1`(po_1200_mp 분배). 체결 큐 — `R_LEDGER=0`(po_1490_mp 체결원장). 리더별 독립 `r_seq` = 프로덕션 파일큐 multi-reader(PS_R_1/PS_R_2) 의미 그대로.
- **replay-safe**: `w_seq`/`r_seq`가 SHM에 상주 → 프로세스 재기동해도 커서 보존(재소비 없음). 파일큐 r_cnt와 동일 내구성. `magic`으로 최초 1회만 zero-init(재기동 시 보존).
- **동시성**: writer 다중(pc_+pb_ 두 시장 동시) → `SEAM_W`는 세마포어(semipc.c)로 `w_seq` 증가 구간 보호. 데이터 copy 후 `w_seq` 발행(store) 순서. 리더는 (qidx,ridx)당 단일이라 `r_seq`는 무락(자기 커서만 갱신), `w_seq`는 정렬된 long 원자읽기.
- **오버플로**: `w_seq - r_seq > SLOTS`(리더 지연)면 `dropped += 유실수`, `r_seq = w_seq - SLOTS`로 최신 창으로 점프 후 진행. **무음 유실 금지 — dropped 누계 + 로그**.
- **검증**: 링 커서 산술(write/read/replay/오버플로/multi-reader/maxrec)은 `test/unit/test_seam_queue.c`(Unity, 순수함수 로컬검증). 배관은 `run_po_e2e.sh`에 pc_ 수신→SEAM_W→po_ 소비 + shm_snap 멱등.

### 5.2 전략(LP·차익거래) 배치·naming 택소노미 (2026-08-07 방향, 소스 업로드 예정)
목표: 실제 **채권 LP 전략·차익거래(통화선물/FX)** 를 다수 인스턴스로 기동. 전략은 체결/시세 이벤트를 소비→판단→주문.

**전략 배치 규칙 (정련, 2026-08-07 — 소스 확인 반영)**:
- **단일시장 전략**(자기 시장 안에서만 리스크, 크로스마켓 헷지 없음) → **그 시장 letter**. 예: 채권 LP는 채권-시장 활동 → `pb_`. (헷지 없으면 자기 시장이 맞다는 운영자 판단.)
- **크로스마켓 전략**(시장을 가로지름, 단일 letter에 귀속 불가) → **`po_`**(OMS 코어 크로스커팅). 예: 차익거래(통화선물×FX).
- **분기점**: 전략이 **다른 시장으로 주문/헷지를 내면 크로스마켓**(po_), 아니면 단일시장(그 letter). 채권 LP가 후일 국채선물로 헷지하면 po_로 재분류.

**실제 소스 매핑 (fep/채권lp, fep/차익거래 — 2026-08-07 업로드)**:
- 채권 LP: `pa_5050_mp.c`(BLP 엔진 blp*.c 임베드, 채권 시세/체결→LP 호가, 단일시장) → **`pb_5050_mp`**.
- 차익거래: `pa_7070_mp.c`(yarb 엔진 임베드, pthread, 통화선물×FX 크로스마켓) → **`po_52xx_mp`**. ⚠`7070`은 규약상 7xxx=시세 충돌 → **5xxx(전략) 밴드로**(2=통화선물차익). ⚠**FX venue `pf_`(미구축) 선결** — 없으면 차익 반쪽.

**시장 대면부(letter=시장) — 시세/주문 코덱·접속 담당**:
- `pb_`=채권, `pc_`=파생(선물/옵션/**통화선물**), `pa_`=현물, **`pf_`=FX(신규 시장 letter, 2026-08-07 확정)** — KRX 아닌 별도 venue라 시세/주문 코덱·접속 분리.

**FX/차익거래 분류 확정 (2026-08-10)**: 차익거래=통화선물×FX 두 leg가 다른 시장 —
- 통화선물(선물 leg) = **KRX 파생 → `pc_`** (yarb `g_md_shm_fut`=FEP FF_SHM 파생시세).
- FX 현물(spot leg) = **외부 FX venue(비-KRX) → `pf_`**(신규 시장 letter; 시세수신+주문송신 대면부; 유안타 FX 프로그램 참고).
- 차익 전략(판단·주문) = **`po_`**(크로스마켓 OMS 코어, Model B). 주문 2-leg: 통화선물→`SEAM_ORDQ_DERIV`(→pc_), FX→`SEAM_ORDQ_FX`(→pf_).

## 6. 빌드 모델 개선 — 컴파일타임 `-D` → 소스분리 + 런타임설정

원칙: **차이의 성격에 따라 처리를 분리**한다.

| 차이 종류 | 현행 | 개선 |
|----------|------|------|
| 시장/프로토콜 (채권 vs 파생 struct·codec) | `#if defined(Bxxxx)` 소스 내 분기 | **시장 모듈 분리**(§3). 전처리 분기 제거, 시장별 파일 |
| 프로세스 인스턴스/역할 (1401 vs 1402 vs 1403, 회선, primary/backup) | 소스당 `-DBxxxx`로 N개 바이너리 | **1 바이너리 + 런타임 식별**. 데몬이 `exec -a p{mkt}_{NNNN}_{type}`로 argv[0] 부여, proc.ini에서 in/out·port·FIFO·기능코드 로드 |
| 전문 크기 (DATA_SIZE) | `-D`로 컴파일 상수 | **런타임 크기**(file.ini/dshm.ini의 record_size 이미 보유) + 버퍼는 시장 최대치로 고정 |
| 플랫폼/기능 플래그 (NO_INISAFE, HOLIDAY_*, osname) | `-D` | **유지** (진짜 빌드타임 관심사) |

핵심 통찰: 인스턴스 차이(포워더 4종 등)는 **이미 proc.ini에 다 있다**. 프로세스는 이미 `argv[0]`에서 자기 식별자를 파싱(`Init_Proc`)하므로, `-DBxxxx`를 지우고 크기만 config에서 읽으면 **한 소스 = 한 바이너리 = N 프로세스(argv[0]로 구분)** 가 된다. 운영 도구(psk.sh, 로그 per process-id)는 argv[0] 프로세스 식별자를 그대로 쓰므로 **영향 없음** — 이 exec -a 패턴은 E2E 하니스에서 이미 검증됨.

효과: `pb_7100_ts.c`의 4개 바이너리 → 1개, `pb_1200_tr.c`의 B1201/B1211 분기 → DR카피는 별도 역할로 config化 또는 얇은 래퍼. 바이너리 수·`#ifdef` 대폭 감소.

4. **파생도 KRX 직접 포트로 수신** (IMECO 아님) → 본 설계의 "전 시장 KRX-direct" 방향과 일치.
5. Meritz도 letter는 계층/기능 축(PA 통합 + PW 연결관리 + PY 콘솔 `cm`타입), 시장은 함수코드+포트로 구분 → A안(letter=시장)은 그보다 진일보한 정리.
