# Plan: INI 서버 구성 분석 문서화

## Feature ID
INI-server-config

## 개요
AP서버(PA 모듈)와 시세서버(PB 모듈)의 INI 구성파일을 분석하여, 프로세스 관계도/데이터 흐름/네트워크 토폴로지를 체계적으로 문서화한다.

## 배경 및 필요성
- FEP 시스템의 AP서버/시세서버 2-tier 구조가 INI 파일로 정의되어 있으나, 전체 관계를 한눈에 파악할 수 있는 문서가 부재
- 신규 인력 온보딩, 장애 대응, 구성 변경 시 참고할 수 있는 아키텍처 문서 필요
- 프로세스 간 FIFO/TCP/UDP 데이터 흐름의 시각적 표현 필요

## 분석 대상 파일

## 특이사항

1. **KOSCOM KTS 경로 비활성**: AP서버 proc.ini의 KRX 직접 주문/체결 프로세스(pa_1301_ts/pa_1201_tr 등 KTS 경로)가 모두 주석처리됨. 현재는 시세서버(PB)를 통한 직접 연결만 사용
2. **Auto Strategy 전부 비활성**: 40개 자동매매 프로세스 모두 Status=S. 운영 시 선택적 활성화
3. **시세서버 경량화**: PB 모듈은 4개 프로세스만 정의. 주로 UDP 시세수신 + 로그관리 역할
4. **2-tier 아키텍처**: 시세서버가 KRX 직접 연결을 담당하고, AP서버는 시세서버로부터 TCP로 데이터 수신
