# 계획: src-commented-code-cleanup

## 개요

활성 src/ 소스 파일(PA, PB, PZ, PW 모듈)에서 남은 `//` 및 `/* */` 주석 처리된 코드를 제거합니다. sub/ 모듈 완료 후 데드 코드 제거 시리즈의 연속. 함수 변화 없는 순수 삭제.

## 문제

sub/ 데드 코드 정리 완료(4단계, ~2,261줄) 후, 활성 파일 (BACK2025/ 및 BACKUP/ 제외)의 모든 `src/**/*.c` 전체 스캔은 ~25개 파일 전체에서 총 ~210+ 줄의 ~150+ 주석 처리된 코드 항목을 보여줍니다. 이들은 더 새로운 구현으로 대체된 이전 함수 호출, 비활성화된 로직, 리팩토링 아티팩트입니다.

## 접근 방식

### 방법

각 파일에 대해 주석 처리된 코드 블록을 식별하고 삭제합니다. 각 파일 내에서 하향식으로 작업합니다. 모든 설명 주석, `// 2025EDIT` 마커, 함수 설명 `/* */` 블록, 한글 주석을 보존합니다.

### 구현 순서

1. **PZ 모듈** (5-6개 파일, ~70줄) — pz_memory_conf.c가 최대 볼륨
2. **PB 모듈** (7개 파일, ~90줄) — pb_1800_ts.c가 가장 복잡
3. **PA 모듈** (13-15개 파일, ~50줄) — 가장 많은 파일이지만 각각 적은 항목
4. **PW 모듈** (1개 파일, ~2줄) — 최소

### 설계 단계 참고

정확한 라인 범위와 FR 항목 사양은 설계 단계에서 각 파일을 읽은 후 결정됩니다. 위의 추정치는 grep 패턴 스캔에서 나온 것이고 개별 블록을 검사할 때 달라질 수 있습니다.

## 영향

| 메트릭 | 값 |
|--------|-------|
| 수정된 파일 | ~25-28 |
| 총 항목 | ~150+ |
| 제거된 총 줄 | ~210+ |
| 추가된 줄 | 0 |
| 순 변화 | ~-210+ 줄 |
| 함수 변화 | 없음 (모든 대상은 주석 처리된 코드) |
| 빌드 영향 | 없음 (주석이 컴파일된 출력에 영향 없음) |

## 위험 평가

- **없음**: 주석 제거는 컴파일된 바이너리에 영향 없음
- **버전 제어**: 제거된 모든 코드는 git 이력 및 BACK2025/ 백업에 보존됨
- **빌드 검증**: `mk.sh src`는 바이트 동일 바이너리 생성해야 함

## 범위 외

- BACK2025/ 및 BACKUP/ 디렉토리 파일 (백업 파일, 활성 코드 아님)
- `// 2025EDIT` 마커 (편집 타임스탬프)
- 한글 설명 주석
- 함수 설명 `/* */` 블록 및 섹션 배너
- `/* */` 인라인 필드 크기 주석 (예: `/* Seq (10) */`)
- src/PA/pa_3100_ts.c (이전 분석에 따르면 활성 빌드에 없음)
- PX 모듈 (이전 정리에서 이미 정리됨)

## 성공 기준

1. 식별된 모든 `//` 및 `/* */` 주석 처리된 코드 블록 제거됨
2. 함수 코드 줄이 변경되지 않음
3. 모든 설명 주석 보존됨
4. 모든 `// 2025EDIT` 마커 보존됨
5. 빌드: `mk.sh src`는 동일 바이너리 생성
