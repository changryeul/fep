### FR-06: 파일별 Device_Close 패턴 -- 90%

#### PA 파일 (pa_1100_ts.c, pa_1200_tr.c, pa_7800_tr.c)

| 측면 | 설계 | 구현 | 일치 |
|--------|--------|----------------|:-----:|
| 패턴 | `#define Device_Close Device_Close_Base` | 래퍼 함수: `void Device_Close(void) { Device_Close_Base(); }` | 변경 |
| 동작 등가성 | 기본만 호출 | 기본만 호출 | 일치 |

변경된 항목 세부사항:

| 항목 | 설계 | 구현 | 영향 |
|------|--------|----------------|--------|
| PA Device_Close 메커니즘 | `#define` 매크로 | 얇은 래퍼 함수 | 낮음 |

설명: 설계는 PA 파일에 대한 전처리기 매크로 `#define Device_Close Device_Close_Base`를 지정했습니다. 구현은 대신 얇은 래퍼 함수를 사용합니다. 둘 다 기능적으로 동일합니다 -- 래퍼 함수는 추가 로직 없이 `Device_Close_Base()`로 단순히 위임합니다. 래퍼 접근법은 두 가지 작은 장점이 있습니다: (1) `Device_Close`을 공유 헤더에서 `extern void Device_Close(void)`로 선언할 수 있게 하여 균등한 인터페이스를 제공하고, (2) 잠재적 매크로 확장 문제를 피합니다. 이는 합리적인 구현 결정입니다.

#### PB 파일 (pb_1100_ts.c, pb_1200_tr.c, pb_7800_tr.c)

| 측면 | 설계 | 구현 | 일치 |
|--------|--------|----------------|:-----:|
| 패턴 | Free_All + INL_Cleanup을 사용한 래퍼 | Free_All + INL_Cleanup을 사용한 래퍼 | 일치 |
| Device_Close_Base() 호출 | 예 | 예 | 일치 |
| Free_All((void*)(long)1) | 예 | 예 | 일치 |
| INL_Cleanup(CLIENT_CTX) | 예 | 예 | 일치 |

결과: **PA 85% (접근법 다름), PB 100%. 결합 90%.**

### FR-07: Err_Msg 추출 -- 65%

이는 가장 큰 갭 영역입니다. Err_Msg 함수는 설계와 구현 간에 크게 다릅니다.

#### 케이스-오류 메시지 매핑

| 케이스 | 설계 메시지 | 구현 메시지 | 일치 |
|------|---------------|----------------------|:-----:|
| 0 | "사용자검증(ID,PASSWORD)오류" | (작업 없음, break만) | 불일치 |
| 1 | "세션관리오류" | "사용자검증(ID,PASSWORD)오류" | 불일치 |
| 2 | "임시오류" | "세션메시지전문수순오류" | 불일치 |
| 3 | "시스템오류" | "헤더회원번호오류" | 불일치 |
| 4 | "응용프로그램 오류" | "데이터일련번호오류" | 불일치 |
| 5 | "일시적 오류" | "메시지길이오류" | 불일치 |
| 6 | "데이터 일련번호 오류" | "업무기마감오류" | 불일치 |
| 9 | "기타오류" | "시스템오류" | 불일치 |
| 101 | "호가접수개시전" | "호가접수개시전" | 일치 |
| 102 | "매매거래시간종료" | "매매거래시간종료후" | 부분 |
| 103 | "호가접수정지" | "호가접수일시중지" | 부분 |
| default | "unknown error" | "RP_DATA recv:unknown 거부사유코드" | 부분 |

#### 동작 차이

| 측면 | 설계 | 구현 | 영향 |
|--------|--------|----------------|--------|
| 케이스 0 동작 | 오류 메시지 로그 | 작업 없음 (break만) | 높음 |
| 케이스 1-6, 9의 sleep | sleep 없음 (3,4,5 제외) | 모든 케이스 1-9에 대해 `sleep(2)` | 중간 |
| 케이스 3,4,5의 sleep | Get_DateMilliTime을 통한 `sleep(NO_TIME)` | `sleep(2)`만 | 높음 |
| 케이스 101 로직 | 로그만 | 로그 + `FirstSeq--` + Get_Time/NoTime 비교 + 조건부 `sleep(10)` + `sleep(2)` | 높음 |
| 케이스 102 로직 | 로그 + Log_Out() | 로그 + `FirstSeq--` + `sleep(2)` + `ErrCd=0` (Log_Out() 이전) | 높음 |
| 케이스 103 로직 | 로그만 | 로그 + `FirstSeq--` + `sleep(2)` | 중간 |
| default | sleep 명시되지 않음 | `sleep(2)` | 낮음 |
| t_time 버퍼 | `char t_time[24]` | memset을 포함한 `char t_time[12]` | 낮음 |
| Time 함수 | `Get_DateMilliTime(t_time)` (케이스 3,4,5) | `Get_Time(t_time)` (케이스 101만) | 중간 |
| Log_Out 이전의 ErrCd = 0 | 없음 | 케이스 102에서 설정됨 | 중간 |
| memset 초기화 | 없음 | 상단의 `memset(t_time, 0, sizeof(t_time))` | 낮음 |

#### 분석

구현의 Err_Msg는 설계 문서의 의사 코드가 아닌 소스 파일의 **실제 프로덕션 동작**을 반영합니다. 설계 문서 (섹션 8.2)는 원본 코드의 단순화된/이상화된 읽기를 기반으로 작성된 것처럼 보이며, 구현은 6개 소스 파일에서 실제 로직을 올바르게 추출했습니다.

주요 근거:
- 케이스 101-103의 `FirstSeq--`는 KRX 시퀀스 관리에 중요합니다 (거부된 주문 재요청)
- 케이스 102의 Log_Out() 이전 `ErrCd = 0`는 무한 루프를 방지합니다
- 케이스 101의 NoTime 비교는 설계가 잘못 케이스 3,4,5에 할당한 사전 시장 개장 sleep 로직을 구현합니다
- 모든 케이스에 균등하게 적용되는 `sleep(2)`는 원본 소스 파일에서 관찰된 실제 동작과 일치합니다

**판정**: 구현이 올바릅니다; 설계 문서의 Err_Msg 의사 코드는 부정확합니다. **설계 문서를 실제 추출된 로직과 일치하도록 업데이트해야 합니다.**

결과: **65% 설계 일치, 그러나 구현이 올바른 버전. 설계 문서 업데이트 권장.**

추가된 항목 세부사항:

| 항목 | 구현 위치 | 설명 | 영향 |
|------|------------------------|-------------|--------|
| `extern char NoTime[]` | fep_common.h:22 | 공유 Err_Msg에서 프로세스별 NO_TIME 지원 | 낮음 -- 의도된 정제 |
| `extern void Device_Close(void)` | fep_common.h:40 | Device_Read/Device_Write가 프로세스별 Device_Close를 호출하도록 활성화 | 낮음 -- 래퍼 접근법 필요 |

설명 (NoTime[]): 설계의 Err_Msg는 `sleep(NO_TIME)`을 직접 사용했으나, `NO_TIME`은 프로세스별 `#define`입니다 (예: 1100/1200의 경우 "0830", 7800의 경우 "0600"). sub/ 코드는 프로세스별 매크로에 액세스할 수 없으므로, 구현은 올바르게 각 프로세스 파일에 `char NoTime[]` 전역을 추가합니다 (`char NoTime[] = NO_TIME;`으로 초기화) 및 헤더에서 `extern`을 선언합니다. 이는 프로젝트 전체에서 사용되는 표준 extern-전역 패턴입니다.

설명 (Device_Close): PA 파일이 `#define` 매크로 대신 래퍼 함수를 사용하므로 (FR-06 참고), `Device_Close`는 헤더에서 `extern`으로 선언되어야 하므로 fep_common.c의 `Device_Read` 및 `Device_Write`가 이를 호출할 수 있습니다. 이는 래퍼 함수 접근법의 필요한 결과입니다.

#### fep_common.c 포함 차이

| 측면 | 설계 | 구현 | 일치 |
|--------|--------|----------------|:-----:|
| 주요 포함 | `fep_sub.h` | `fep_fepp.h` | 변경 |
| 자체 포함 | `fep_common.h` | `fep_common.h` | 일치 |

설명: 설계는 `#include "fep_sub.h"`를 지정했습니다 (sub/ 파일의 표준). 그러나 구현은 `#include "fep_fepp.h"`를 사용합니다. 이는 fep_common.c가 SHM 매크로 (`TCP2_LINE_ST`, `TCP2_LINE_GU`, `TCP2_PORT_NO`, `INT_SEQ`, `LOAD_CNT` 등)를 필요로 하기 때문입니다. 이는 `fep_sub.h`를 통해서는 사용 불가능하지만 `fep_fepp.h`를 통해서는 사용 가능합니다. `fep_fepp.h` 헤더는 src/ 프로세스 파일의 표준 포함입니다; fep_common.c는 추출된 프로세스 레벨 로직을 포함하므로 이를 포함하는 유일한 sub/ 파일입니다. 이는 유효한 구현 결정입니다.

결과: **88% -- 2개 의도된 추가, 1개 포함 변경, 모두 정당화됨.**

## 원인 분석

주요 갭 소스는 **FR-07 (Err_Msg)**입니다. 설계 문서의 섹션 8.2의 의사 코드는 소스 파일의 실제 Err_Msg 로직을 정확하게 나타내지 않습니다. 구체적으로:

1. **오류 코드 매핑**: 설계는 추상 오류 카테고리를 할당했습니다 (예: 케이스 3 = "시스템오류") 반면 실제 코드는 KRX 특정 거부 코드를 사용합니다 (케이스 3 = "헤더회원번호오류"). 구현은 올바르게 실제 프로덕션 로직을 추출했습니다.

2. **sleep(NO_TIME) vs sleep(2)**: 설계는 잘못 NoTime 기반 sleep을 케이스 3,4,5에 할당했습니다. 실제로, NoTime 비교는 케이스 101 (사전 시장 개장 거부)에만 적용되며, 이는 시간 기반 대기가 의미 있는 유일한 시나리오입니다.

3. **FirstSeq-- 롤백**: 설계는 케이스 101-103의 `FirstSeq--` 작업을 생략했습니다. 이는 중요한 프로덕션 로직입니다 -- KRX가 이러한 코드로 메시지를 거부할 때, 메시지를 재전송할 수 있도록 시퀀스 번호를 롤백해야 합니다.

4. **ErrCd = 0 리셋**: 설계는 케이스 102의 `Log_Out()` 이전 `ErrCd = 0`을 생략했습니다. 이것 없이, 오류 코드는 유지되며 후속 처리에서 잘못된 동작을 초래할 수 있습니다.

**결론**: 구현이 원본 소스 파일보다 설계 의사 코드에 더 충실합니다. 설계 문서를 실제 추출된 로직과 일치하도록 업데이트해야 합니다.
