# 계획: magic-numbers-extraction

## 개요

FEP 코드베이스에 걸쳐 원시 숫자 리터럴(매직 넘버)을 명명된 상수로 바꿉니다. 세 가지 카테고리를 대상으로 합니다: KRX 데이터 버퍼 크기 `4096`, UDP 소켓 수신 버퍼 `1228800`, KRX 헤더 길이 `82` (기존 상수 사용 가능하지만 한 위치에서 미사용).

## 배경

FEP 코드베이스는 중요한 프로토콜/시스템 크기를 나타내는 여러 하드코딩된 숫자 리터럴을 사용합니다. 이러한 매직 넘버는 가독성을 감소시키고, 값이 변경되어야 하는 경우 유지 보수 위험을 만듭니다. 주요 발견:

- **4096**: 데이터 버퍼 크기로 사용됨 (`DataBuff[4096]`, `Chg_Data[4096]`, `S_Data[4096]`, 경계 확인, FIFO 버퍼). 17개 활성 파일에서 26개 발생.
- **1228800**: UDP 소켓 수신 버퍼 크기 (= 1200 * 1024 = 1200KB). 2개 파일에서 2개 발생.
- **82**: KRX 헤더 길이. 이미 `pa_struct.h`에서 `KRX_HEAD_LEN`으로 정의되어 있지만, `pb_8200_tr.c`는 원시 `82`를 사용합니다.
- **DATA_SIZE**: 프로세스별로 다름 (200, 400, 700, 2048) `-D` 컴파일 타임 정의를 통해. 설계상 이유이므로 범위 외입니다.

## 범위

### 카테고리 A: 새로운 상수 정의 (`inc/fep_fepp.h`)

| 상수 | 값 | 목적 |
|----------|-------|---------|
| `KRX_DATA_BUFF_SIZE` | `4096` | KRX 메시지 교환을 위한 표준 데이터 버퍼 크기 |
| `UDP_SOCK_RCVBUF_SIZE` | `1228800` | UDP 소켓 수신 버퍼 (1200KB) |

배치: `inc/fep_fepp.h` — `src/` 및 `sub/`에 걸쳐 141개 파일에 포함됩니다. 단순 래퍼 헤더.

## 제외 사항

- `DATA_SIZE` 리터럴: 프로세스마다 `-D` 정의를 통해 다름 (설계상)
- `inc/queue.h` `MAXSIZE 4096`: 관련 없는 큐 상수
- `pa_5200_qs.c` `MAXSIZE 4096`: 큐 상수, 다른 목적
- `pa_5000_qr.c` `MAXSIZE 4096`: `/* */` 블록 주석 내 데드 코드
- `BACK2025/`, `JC_OLD/`, `.org` 파일: 레거시/백업 파일

## 위험 평가

- **위험**: 낮음 — 모든 변경은 상수-리터럴 대체입니다. 로직 변경 없음.
- **컴파일**: `fep_fepp.h`의 새로운 상수가 모든 141개 포함 파일로 전파됩니다. 기존 정의와 충돌 없음.
- **테스트**: 빌드 검증 (`mk.sh all`)으로 충분합니다.
- **롤백**: 상수 정의 및 리터럴 대체의 간단한 되돌리기.

## 예상 영향

- 18개 파일 (17개 소스 + 1개 헤더)에 걸쳐 29개 리터럴 대체
- `inc/fep_fepp.h`의 2개 새로운 `#define` 상수
- 순 라인 변경: ~+2줄 (상수 정의), ~0 순 변경 (대체는 같은 줄)
- 기능 변경 없음
