# 계획: pa-pb-8100-cleanup

## 개요

클라이언트 통신 전송 프로세스인 pa_8100_ts.c 및 pb_8100_ts.c에서 주석 처리된 데드 코드 및 사용되지 않는 변수를 정리합니다. 기능 변경 없는 순수 삭제.

## 문제

`#if 0` 데드 코드 정리 (1,945줄)를 완료한 후, 다음 데드 코드 카테고리는 `/* */` 스타일 주석 처리된 블록입니다. pa/pb_8100_ts.c 클라이언트 통신 파일에 포함:

1. **주석 처리된 코드 블록** — 비활성화된 검증 로직, 포기된 HOLIDAY 확인 흐름, 이전 seq 리셋 코드
2. **사용되지 않는 변수** — `arry_cnt`, `arry_len`, `arry_dat` 선언되었으나 참조되지 않음
3. **주석 처리된 함수 호출** — `//Device_Close()` 양쪽 파일

이들은 활성 코드를 모호하게 하고 줄 수를 늘립니다.

## 접근 방식

각 항목에 대해: 주석 처리된 코드 블록 또는 사용되지 않는 변수 선언을 삭제합니다. 다른 변경은 없습니다.

### 특수 사례

1. **pb_8100_ts.c HOLIDAY_APPLY** (107-119줄): 주석 처리된 블록을 제거한 후, 107줄의 `break;`은 `tp = localtime(&t);` 호출 이후 while 루프 본체의 유일한 문장으로 남습니다. 이는 의도된 것입니다 — PB의 HOLIDAY_APPLY 블록은 단순히 즉시 중단합니다.

2. **pb_8100_ts.c Make_Send_Msg** (640-666줄): `/* 2025 */` 주석은 이 검증 로직이 2025년에 비활성화됨을 나타냅니다. `#if defined B8101 || B8111 || B8116` / `#elif defined B8105 || B8117 || B8118` 전처리기 지시문은 활성 코드를 괄호로 묶으므로 유지해야 합니다 (638줄의 `else` 블록은 여전히 활성). `#if` 분기 내부의 `/* ... */` 콘텐츠만 제거됩니다.

3. **pa_8100_ts.c HOLIDAY_APPLY** (103-114줄): `/* ... */` 블록은 주말 확인의 `else` 절 내부에 있습니다. 제거 후, 활성 코드 (`Log` + `break`)는 남습니다.

## 위험 평가

- **없음**: 모든 변경은 주석 및 사용되지 않는 변수 제거 — 컴파일된 출력에 0 효과
- 컴파일러는 이미 이 블록을 무시합니다
- 버전 제어는 모든 제거된 코드를 보존합니다

## 범위 외

- 전체 pa/pb_8100_ts dedup (7개 동일 함수를 공유 라이브러리로 추출) — 전역 변수 의존성으로 인해 별도 기능으로 연기됨
- 모든 기능 코드 변경
- 기타 PA/PB 파일

## 성공 기준

1. 양쪽 파일에서 모든 `/* ... */` 주석 처리된 코드 블록 제거됨
2. 모든 `//` 주석 처리된 코드 제거됨
3. 사용되지 않는 변수 제거됨
4. 기능 코드 변경 없음
5. 빌드: `mk.sh src`는 동일 바이너리 생성
