# PA 모듈 코드 품질 감사 — 계획 문서

> **기능**: PA (거래 모듈 코드 품질 감사)
> **프로젝트**: FEP (KRX 프론트엔드 프로세서)
> **작성자**: Claude Code
> **날짜**: 2026-02-26
> **상태**: 초안

---

## 목표

모든 32개 PA (거래) 모듈 소스 파일의 체계적 코드 품질 감사. 버그, 안전하지 않은 패턴, C89 준수 문제, 데드 코드 수정. 완료된 PB 모듈 감사(100% 일치율, 28개 발견사항)의 패턴과 교훈을 활용.

## 범위

- **범위 내**: `st01/src/PA/`의 모든 32개 `.c` 파일
- **범위 외**: 헤더(`inc/`), 공유 라이브러리(`sub/`), 기타 모듈(PB/PX/PZ) -- 이미 감사됨
- **미연기**: C++ 주석 변환(M2, 6개 파일에 걸친 약 257개) -- 낮은 영향, 높은 볼륨

## 발견사항 요약

| 심각도 | 개수 | 주제 |
|----------|-------|-------|
| CRITICAL | 5 | 미초기화 변수, 누락된 중괄호, 누락된 반환 경로 |
| HIGH | 6개 그룹 (29+ 위치) | sizeof 버그, 전처리기 defined(), 포맷 문자열, 0으로 나누기, 신호 안전, 데드 코드 |
| MEDIUM | 5개 그룹 (15 위치) | 하드코딩된 IP, 누락된 포함, 잘못된 TR 코드, 미사용 변수 |
| LOW | 3개 그룹 | FIFO 드레인 스타일, 중복 로그, 미사용 변수 |
| **합계** | **45** | |

> **H5/FR-17에 대한 참고**: 신호 핸들러 안전은 이미 `sub/` 파일의 `signal-handler-safety` 보관된 기능에서 해결되었음. PA 파일은 다른 패턴(`Exit_Process()` 직접 호출)을 사용. 전체 완화에는 이러한 컨텍스트에서 `Exit_Process()`를 `_exit()`로 안전하게 교체할 수 있는지 여부를 이해해야 함. 이 배치는 부분적으로 미연기될 수 있음.

## 위험 평가

| 위험 | 영향 | 완화 |
|------|--------|------------|
| FR-03 (누락된 중괄호)는 #ifdef 보호될 수 있음 | 빌드 변형이 컴파일되지 않을 수 있음 | 이 코드 경로를 포함하는 -D 정의 확인 |
| FR-14 (잘못된 TR 코드)는 비즈니스 로직 변경 | LP 채권 자동 취소 동작 | 배포 전 비즈니스 검증 필요 |
| FR-12 (123.123.123.123)는 의도된 IMECO 자리 표시자일 수 있음 | 제거하면 IMECO 핸드셰이크 손상 가능 | 변경 전 IMECO 프로토콜 문서 검토 |
| 신호 핸들러 변경(FR-17)은 충돌 복구에 영향 | 프로세스가 제대로 정리되지 않을 수 있음 | TEST 환경에서 철저히 테스트 |
