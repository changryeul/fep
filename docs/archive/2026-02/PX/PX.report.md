### 2.3 실행 단계 (구현)

  ```c

  // 새로: #elif defined(sun) || defined(_AIX) || defined(__linux)
  ```

**배치 3: Medium 수정 (FR-31..FR-36)**
- FR-31: px_memok.c의 continue_flag 초기화 및 재설정

- FR-36: px_chktrcnt.c의 도달할 수 없는 exit(1)을 exit(OK)로 변경 (기능적으로 동등한 제거)

**배치 4: Low 수정 (FR-37..FR-38)**

- FR-38a/b/c: 3개 chkgap 파일에서 사용하지 않는 sub[4]와 해당 memset 제거

### 3.1 유형별 버그 카테고리

#### 카테고리 1: 잘못된 배열 인덱스 (1개 발견)

#### 카테고리 2: 누락된 함수 리턴 (2개 발견)

| FR | 파일 | 이슈 | 영향 | 수정 |
|----|------|-------|--------|-----|
| FR-02 | px_setfname.c:180-196 | `int` 함수가 f_count=0일 때 끝에 도달 | 빈 파일 목록의 정의되지 않은 동작 | exit(FAIL) + return(0) 추가 |
| FR-03 | px_setdname.c:180-196 | `int` 함수가 d_count=0일 때 끝에 도달 | 빈 DSHM 목록의 정의되지 않은 동작 | exit(FAIL) + return(0) 추가 |

**분석**: 두 함수 모두 루프 내에 조기 종료 경로가 있지만 0-반복 케이스 처리 실패. 낮은 위험, 프로세스는 어쨌든 오류로 종료.

#### 카테고리 3: 초기화되지 않은 변수 (5개 발견)

| FR | 파일 | 변수 | 영향 | 수정 |
|----|-------|-----------|--------|-----|
| FR-04 | px_chkgap_auto1.c | recv_sec, send_sec, start_tm, end_tm | 루프가 비어있으면 산술에서 사용 | `= 0`으로 초기화 |
| FR-05 | px_chkgap_man.c | recv_sec, send_sec, start_tm, end_tm | 루프가 비어있으면 산술에서 사용 | `= 0`으로 초기화 |
| FR-06 | px_chkgap_auto3.c | recv_sec, send_sec, start_tm, end_tm | 루프가 비어있으면 산술에서 사용 | `= 0`으로 초기화 |

**분석**: CRITICAL 심각도. FR-31은 특히 위험: 한 번 1로 설정되면 continue_flag가 영구적으로 설정된 상태 유지, 자동으로 모든 다음 설정 줄 건너뜀.

#### 카테고리 4: 전처리기 구문 문제 (23개 발견)

| 패턴 | 이슈 | 파일 | 영향 | 수정 |
|---------|-------|-------|--------|-----|
| `#elif defined sun \|\| _AIX \|\| __linux` | `_AIX`와 `__linux`가 `defined()`로 래핑되지 않음 | 23개 파일 | 비-Linux 플랫폼에서 전체 블록 건너뜀 가능 | 모두 래핑: `defined(_AIX)` 등 |

**분석**: 현재 Linux에서는 "우연히 올바름" (여기서 `__linux=1`)이지만 의도를 벗어남. HIGH 심각도, 여러 파일에 영향을 주는 광범위한 패턴.

## 6. 교훈

### 6.1 잘된 점

1. **체계적 배치 실행**: 38개 발견을 4개 명확한 배치 (Critical, High, Medium, Low)로 조직하면 구현 및 검증이 간단해짐. 각 배치는 독립적으로 컴파일 가능.

2. **100% 첫 번째 패스 정확도**: 반복 불필요. 다음을 반영:
   - 명확한, 상세한 설계 사양과 이전/새로 만들기 코드 비교
   - C89 의미론의 올바른 이해 (초기화되지 않은 변수, 리턴 요구사항)
   - 검증 방법론 (줄별 소스 비교)

3. **패턴 인식**: HIGH 심각도 배치 (배치 2)는 23개 동일한 수정. `replace_all` 전략을 사용하면 개별 파일 오류 도입 없이 대량 적용 가능.

4. **이전 감사 활용**: PB 감사 (28개 발견, 100% 일치) 및 PA 감사 (38개 발견, 100% 일치)의 패턴이 방법론 및 문제 분류에 대한 신뢰성 제공.

5. **통합된 발견**: FR-33이 FR-07과 통합됨 (동일 파일, 동일 변수) 중복 감소 및 이중 수정 방지.

6. **경미한 편차**: FR-36 편차 (exit(OK) vs 제거)는 기능적으로 동등하고 분석에서 명시적으로 기록됨.

### 6.2 개선 영역

1. **전처리기 패턴**: 23개 파일의 동일한 전처리기 버그 제안:
   - 공통 템플릿에서의 복사-붙여넣기 (향후 예방 식별됨)
   - 보일러플레이트 생성 스크립트의 버그
   - 권장: 빌드 파이프라인에 린터 규칙 `defined(X) || defined(Y)` 확인 추가

2. **초기화되지 않은 변수 감지**: chkgap 파일의 `recv_sec`, `send_sec`, `start_tm`, `end_tm` 및 runstop의 `reload_flag` 같은 변수를 조기에 포착할 수 있음:
   - 정적 분석 도구 (splint, clang analyzer)
   - 컴파일러 플래그 `-Wuninitialized`
   - 권장: `Make_*.mk` 파일에서 `-Wall -Wextra -Wuninitialized` 활성화

3. **하드코딩된 호스트명 취약성**: FR-34 수정 (podm11/podm12 추가)은 여전히 유지보수에 취약함. 더 나은 접근:
   - `pkg_env.sh`에서 이미 사용 가능한 `_FEP_DIV` 환경 변수 사용
   - 설정 파일에 호스트명 매핑 저장 (`dshm.ini` 또는 `daemon.ini`)
   - 권장: 문자열 비교 대신 환경 변수 확인 사용으로 향후 향상

4. **빈 스텁 처리**: px_chkgap.c는 논리가 없는 자리 표시자. 권장:
   - 미사용/레거시임을 설명하는 주석 추가
   - 다음 릴리스에서 폐기 통지 고려 또는 제거
   - 또는 px_chkgap_auto1.c와 통합

### 6.3 다음 번 적용

1. **구현 전 체크리스트**:
   - [ ] 감사 전 모듈에서 정적 분석기 실행
   - [ ] 빌드 플래그 확인 (모든 경고 활성화)
   - [ ] 모든 파일의 유사 패턴 검토 (보일러플레이트 버그 조기 포착)

2. **설계 패턴 라이브러리**:
   - 발견된 공통 패턴 문서화: 전처리기 확인, 초기화되지 않은 변수, 누락된 리턴
   - 향후 감사를 위한 빠른 참조 만들기

3. **자동화된 검증**:
   - `defined X || Y || Z` 패턴 (모두 `defined()`로 래핑되지 않음) 확인 스크립트
   - 모든 분기 종료 함수 감지 및 말단 코드 경로 검증 스크립트

4. **배치 전략 확인**:
