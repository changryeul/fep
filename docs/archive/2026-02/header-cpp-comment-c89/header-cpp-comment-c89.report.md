## 5. 구현 하이라이트

### 코멘트 변환 패턴

1. **인라인 구조체 필드 코멘트**: `int x;  // description` → `int x;  /* description */`
2. **독립형 줄 코멘트**: `// section header` → `/* section header */`
3. **코멘트 아웃 코드**: `// #include <foo.h>` → `/* #include <foo.h> */`
4. **병합된 코멘트**: `/* text */` 뒤에 `// more text` → `/* text more text */` (krx_mk.h 줄 310에 적용됨)

### 특수 처리

**krx_mk.h 거짓 양성 감지**:
- 설계 문서가 37개 `//` 발생을 계산
- 분석이 `/* ... */` 블록 코멘트 내부의 8개 거짓 양성 식별 (줄 7-43, 1257, 1387)
- 이것들은 블록 코멘트 내부의 평문, 활성 C++ 코멘트 아님
- 올바른 동작: 건너뜀 (이미 C89 블록 코멘트 보호 내부)
- **결과**: 29개 활성 변환 + 8개 올바르게 건너뜀 = 100% 정확도

**fep_sub.h 데드 코드 처리**:
- 6개 코멘트 아웃된 `#include` 및 `#define` 줄 삭제 (이전 정리 규칙과 일관)
- 추적 코멘트 추가: `/* Start of XML (removed: libxml includes - unused) */` 줄 23에
- 삭제된 컨텐츠의 코드 이력 및 문서화 유지

## 6. 교훈

### 성공한 부분

1. **정확한 패턴 일치**: 명확한 변환 규칙(`// comment` → `/* comment */`)으로 최소 모호성으로 높은 정확도 활성화
2. **설계 명확성**: 설계 문서가 특수 경우 식별 (데드 코드 삭제, 블록 내부 거짓 양성) 오류 방지
3. **0 위험 수정**: 코멘트 전용 변경으로 코드 로직 영향 없음으로 0 함수 위험
4. **배치 구성**: 파일 크기별 처리 (가장 큰 것 먼저)로 논리적 워크플로우 구조 제공
5. **거짓 양성 인식**: 8개의 남은 `//`을 `/* */` 블록 내부의 거짓 양성으로 식별하는 것이 C 코멘트 중첩 규칙의 올바른 이해 입증

### 개선 영역

1. **초기 스캔 품질**: 원본 계획 스캔이 `grep "//"`를 사용하여 활성 C++ 코멘트와 블록 코멘트 내 텍스트를 구분하지 않음 — 향후 감사는 컨텍스트 인식 분석 사용 권장
2. **데드 코드 일관성**: fep_sub.h 데드 코드가 변환 대신 삭제됨으로 설계 문서가 변환으로 계산 — 미리 데드 코드를 삭제해야 하는지 변환해야 하는지 명확히 함
3. **인코딩 아티팩트**: fep_file.h의 일부 한국 코멘트에서 minor 인코딩 고려 — 인코딩 인식 편집 도구로 신뢰성 개선 가능

### 적용 패턴

1. **코멘트 병합**: `// text`가 `/* text */`를 바로 따를 때, 인접 코멘트 생성 대신 단일 `/* combined text */`로 병합
2. **추적 코멘트**: 데드 코드 블록 삭제 시, 삭제된 내용과 이유를 문서화하는 설명 코멘트 추가
3. **전체 디렉토리 검증**: 대상 변경 후, 전체 활성 디렉토리를 스캔하여 잔여 항목을 포착하고 엣지 케이스 캐치
