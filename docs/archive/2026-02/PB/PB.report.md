**근거**: 단일 주문 처리 (MAX_CNT=1), DataBuff[78]의 하드코딩된 "001"로 확인됨.

#### 배치 2: Analyze_Data() 누락된 기본값 반환 (FR-04, FR-05, FR-06)

- FR-06: pb_1200_tr.c — `Header_Fmt.MsgType` 사용

#### 배치 3: 전처리기 `defined` 키워드 (FR-07, FR-08, FR-09)

**완료**: 100% (3/3)

- FR-18b: 보너스: pb_1200_tr.c에서 동일한 버그 수정 (2개 위치)

1. **데이터 무결성**: FR-02/03 미초기화 `datacnt`는 KRX 거래소에 잘못된 레코드 수를 보낼 수 있어 트랜잭션 상태를 손상시킬 수 있음
2. **제어 흐름**: FR-01 누락된 break로 인해 상태 머신이 하트비트 후 잘못된 핸들러를 실행하여 잠재적으로 연결을 잃을 수 있음
3. **메모리 안전성**: FR-11 w_gbn=0 초기화로 배열 범위 초과 접근 (`out_f[-1]`)

### 6.2 공유 라이브러리 마이그레이션 전략

배치 5 (pb_1800_ts.c 중복 제거)는 PA/PB 중복 제거를 위한 FmtPtr 패턴을 보여줍니다:

- 각 프로세스는 구조체 유형 차이를 해결하기 위해 `void *FmtPtr = (void *)&{S_Fmt|KR_Fmt}` 정의
- 공유 `fep_encrypt.c` 및 `fep_common.c` 함수는 `FmtPtr`를 사용하여 투명하게 두 포맷을 처리
- 결과: ~180개 중복 암호화/로깅 코드 라인이 공유 라이브러리로 통합

## 7. 교훈

### 7.1 잘된 점

1. **설계 방법론**: 설계 문서에서의 정확한 코드 인용(이전/이후 블록)은 0회 반복으로 100% 일치율을 달성했습니다. 이는 의사코드보다 "실제 코드 인용" 접근 방식을 검증합니다.

2. **배치 그룹화**: 28개 항목을 심각도 및 테마별로 8개의 논리적 배치로 구성하면 순차적이고 컴파일 가능한 진행을 가능하게 하고 인지 부하를 줄였습니다.

3. **모듈 특정 감사**: PB 고유 버그(vs. 시스템 전체 패스)에 집중하면 광범위한 패턴이 놓친 이슈를 발견하여 대상 감사의 유효성을 검증했습니다.

4. **중복 제거 패턴 검증**: pb_1800_ts.c의 공유 라이브러리로의 마이그레이션은 FmtPtr 패턴이 PA/PB 모듈 전반에 걸쳐 안정적으로 작동함을 확인하여 향후 통합의 길을 열었습니다.

### 7.2 개선 영역

1. **FR-27 연기**: 의도적으로 연기되었지만 남은 ~80개 `//` 주석은 불완전한 C89 변환을 나타냅니다. 빠른 후속 기능으로 일정을 잡을 것을 권장합니다.

2. **전처리기 변형 분석**: FR-07/08/09 수정은 프로세스 ID 빌드 플래그(-DB1201, -DB1601 등) 이해를 요구했습니다. 이러한 조건부 빌드 패턴의 더 나은 문서화는 향후 감사를 도울 것입니다.

3. **하드코딩된 값 감지**: FR-20/21/22/23 이슈(하드코딩된 IP, NIC)는 구성 강제 시행의 체계적 감사 필요성을 시사합니다. 일부 프로세스는 여전히 진정한 구성 기반 초기화 대신 구성 재정의를 사용합니다.

### 7.3 향후 권장사항

1. **C++ 주석 정리**: FR-27을 독립형 마이크로 기능으로 일정을 잡아 C89 준수를 완료합니다.

2. **UDP 소켓 견고성**: FR-19 0으로 나누기 보호는 다른 UDP/네트워크 코드 경로도 유사한 경계 확인이 필요할 수 있음을 시사합니다.

3. **구성 강제 감사**: 모든 모듈에 걸친 남은 하드코딩된 구성 재정의의 후속 감사 (FR-20/21과 유사).

4. **공유 라이브러리 통합**: 다른 모듈(PA, PW, PX)을 위해 fep_common.c 및 fep_encrypt.c로 중복 함수를 추출하는 패턴 계속.
