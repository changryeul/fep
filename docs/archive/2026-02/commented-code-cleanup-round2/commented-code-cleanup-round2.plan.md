# 계획: commented-code-cleanup-round2

## 개요

sub/, PB 및 PX 모듈에 걸쳐 14개 활성 소스 파일에서 남은 `/* */` 주석 처리된 코드 블록 및 `//` 주석 처리된 코드 행을 제거합니다. `dead-code-cleanup` (#if 0 블록) 및 `pa-pb-8100-cleanup`의 후속. 기능 변경 없는 순수 삭제.

## 문제

~1,945줄의 `#if 0` 데드 코드 및 pa/pb_8100_ts.c에서 64줄을 제거한 후, 코드베이스는 여전히 `/* */` 블록 및 `//` 행에 ~170줄의 주석 처리된 코드를 포함합니다. 이는:

1. **새 구현으로 대체된 이전 코드** — sprintf가 snprintf로 대체, write가 오류 확인 write로 대체, memcpy가 직접 할당으로 대체 등
2. **비활성화된 함수 호출** — `//Exit_Process()`, `//Device_Close()`, `//INL_Initialize()` 등
3. **구식 변수 선언** — 이전 버퍼 크기가 더 큰 것으로 대체됨
4. **데드 대체 코드 경로** — 이전 if/else 분기, 이전 printf 형식 문자열이 수정된 버전으로 대체됨

모든 원본 코드는 버전 제어 및 BACK2025/ 백업에 보존되어 있습니다.

## 접근 방식

### 방법

각 파일에 대해 주석 처리된 행 또는 블록을 삭제합니다. 다른 변경은 없습니다. 각 파일 내에서 아래에서 위로 작업하여 줄 번호를 보존합니다.

### 특수 사례

1. **pb_1200_tr.c 828-845줄**: 전체 `/* 2번째 */` 주석 + `#if defined B1201` + `/* */` 블록 + `#endif`는 데드 코드입니다. `/* */` 블록이 조건 내 유일한 콘텐츠이기 때문입니다. 모든 18줄을 제거합니다. 참고: 847줄의 Log 문은 첫 쓰기로부터의 오래된 `rt`을 참조하지만, 이는 이 정리 범위가 아닌 미래 수정을 위한 기능적 문제입니다.

2. **pb_1200_tr.c 481-514줄**: `/* */` 블록은 활성 코드 (454-480줄) 이후의 `#elif defined B1601` 섹션 끝에 있습니다. 515줄 (`#endif`)은 보존되어야 합니다.

3. **log_proc.c 178-195 및 253-269줄**: 각각 두 개의 연속된 `/* */` 블록 (이전 sprintf + 이전 Tmp 버퍼 패턴)을 포함합니다. 두 블록을 단위로 제거합니다.

4. **`// 2025EDIT` 마커** (log_proc.c 171, 196, 247, 270줄): 이 편집 타임스탬프 주석은 이 정리 범위 외입니다. 2025년 편집을 표시하고 역사적 컨텍스트로 작용하므로 최소한이라도 유지합니다.

### 구현 순서

1. sub/ 파일 (8개 파일) — 라이브러리 파일 먼저, log_proc.c 가장 큰 대상
2. src/PB/ 파일 (2개 파일) — pb_1200_tr.c 및 pb_1100_ts.c
3. src/PX/ 파일 (4개 파일) — 유틸리티/모니터링 프로세스

## 범위 외

- `// 2025EDIT` 마커 (편집 타임스탬프 주석, 데드 코드 아님)

- `/* ... */` 섹션 배너 및 함수 종료 마커
