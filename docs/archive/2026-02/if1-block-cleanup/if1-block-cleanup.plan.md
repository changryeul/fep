# 계획: if1-block-cleanup

## 개요

활성 src/ 소스 파일에서 모든 `#if 1` / `#if (1)` 항상 참인 전처리기 블록을 제거합니다. 이는 항상 컴파일되는 활성 코드를 래핑하는 구식 디버그/테스트 조건입니다. 정리는 내부 코드를 풀어줍니다 (유지) 및 `#if`/`#endif` 행만 제거합니다. 기능 변경 없음.

## 문제

데드 코드 정리 시리즈 (~2,750개 줄 제거, ~90개 파일)를 완료한 후, 코드베이스는 여전히 11개 활성 소스 파일에 걸쳐 16개의 `#if (1)` / `#if 1` 블록을 포함하고 있습니다. 이러한 블록:

1. **항상 참인 조건** — `#if (1)` 및 `#if 1`은 항상 참으로 평가되므로, 래핑된 코드는 항상 컴파일됩니다. 전처리기 가드는 의미가 없습니다.
2. **테스트/디버그 로깅** — 많은 것이 개발 중에 추가되어 디버그 출력을 토글하도록 했지만, 끄지 않았습니다.
3. **소켓 옵션 설정** — `SO_BROADCAST` setsockopt 호출이 방송이 테스트될 때 `#if (1)`로 래핑됩니다.
4. **유지 보수 노이즈** — 읽기 흐름을 모호하게 하고 코드가 선택적일 수 있음을 시사합니다.

모든 원본 코드는 버전 제어 및 BACK2025/ 백업에 보존되어 있습니다.

## 구현 전략

1. **풀어만 내기** — `#if (1)` / `#if 1` 및 `#endif` 행을 제거합니다. 모든 내부 코드를 현재 들여쓰기 레벨로 유지합니다.
2. **각 파일 내에서 아래에서 위로** — 더 높은 줄 번호를 먼저 처리하여 줄 참조를 보존합니다.
3. **모듈별 배치** — PA 먼저 (9개 파일), 그 다음 PB (1개 파일), PW (1개 파일), PZ (1개 파일).

## 위험 평가

- **위험**: 없음. `#if 1`은 항상 참으로 평가됨 — 가드를 제거해도 컴파일이나 동작에 영향 없음.
- **검증**: `mk.sh src`는 동일한 바이너리를 생성해야 합니다 (개체 파일에서 `diff`로 검증 가능).
- **롤백**: Git 되돌리기 또는 BACK2025/ 사본.

## 범위 외

- `#if defined` / `#elif defined` 블록 (활성 플랫폼 조건)
- `#ifdef` 블록 (사용 중인 기능 토글)
- `#if 0` 블록 (없음 — 이미 데드 코드 정리에서 정리됨)
- BACK2025/, BACKUP/, JC_OLD/ 디렉토리의 파일
- 한글 설명 주석
- `// 2025EDIT` 타임스탬프 마커
